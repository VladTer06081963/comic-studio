# Аудит: Стандартизация портов (Ports Audit & Standardization)

## 1. Контекст
В проекте исторически возникла несогласованность в используемых сетевых портах по умолчанию. Разные компоненты системы (Web-сервер, Telegram-бот, MCP-сервер) ссылались либо на порт `3000`, либо на `3300`, что приводило к путанице и ошибкам интеграции при локальном запуске, если не все переменные окружения были строго заданы.

## 2. Что выявлено (Аудит)
- `web/server.js` (Express) по умолчанию запускается на порту `3000` (если не задан `PORT` в `.env`).
- Вся документация (`README.md`, `DEMOPRODACTION.md`, `PRD.md`) описывает порт `3000`.
- `mcp-server/index.js` по умолчанию ищет Web API на `http://127.0.0.1:3300`.
- `tg-bot/bot.js` жестко привязан к `http://127.0.0.1:3000` в справочных сообщениях и делает фоллбэк на него для внутренних API вызовов.
- Пользователь локально запускал `web/server.js` на порту `3300` (через `.env`), из-за чего Telegram-бот давал неверные ссылки в справке.

## 3. Решение (План)
Было принято решение стандартизировать **порт 3000** как единственный порт по умолчанию во всей кодовой базе:
1. Зафиксировать `API_BASE_URL` fallback в `mcp-server/index.js` на `3000`.
2. Избавиться от хардкода `http://127.0.0.1:3000` в текстах `/help` в `tg-bot/bot.js`, используя динамические переменные (`WEB_PUBLIC_URL` / `WEB_API_URL`).
3. Расширить `.env.example`, четко указав `PORT=3000` и связанные переменные.
4. Отказаться от OpenSpec-документа, так как это рефакторинг конфигурации (tech debt), не меняющий поведение API.

## 4. Статус
Начат процесс реализации.
