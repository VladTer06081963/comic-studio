# Фиксация (Fixation)

**Фиксация** — стандартная процедура полного закрытия и документирования любой задачи. Обязательна для всех мутирующих задач.

## Процедура (4 шага)

### 1. OpenSpec Change (если задача затрагивает код/спек)

Если есть незаархивированный change в `openspec/changes/`:
1. Проверить статус: `openspec status --change <name> --json`
2. Синхронизировать delta specs в main specs (если есть)
3. Архивировать: переместить в `openspec/changes/archive/YYYY-MM-DD-<name>/`

### 2. Аудит в `summary/audit/`

Создать файл: `summary/audit/<NNN>_<slug>.md`

```markdown
# Аудит: <тема>

## 1. Контекст
## 2. Что сделано
## 3. Статус
```

### 3. Задачи в `summary/tasks/`

Создать/обновить: `summary/tasks/<NNN>_<slug>.md`

```markdown
# Задачи: <тема>

## Статус: ✅ Done

| ID | Задача | Оценка | Статус |
|---|---|---|---|
| 1 | ... | ... | ✅ Done |
```

### 4. Git Commit

```bash
git add <все файлы задачи>
git commit -m "<type>: <description>"
git push  # если есть remote
```

## Объём фиксации

| Что | Где |
|-----|-----|
| Аудит (что сделано, выводы) | `summary/audit/` |
| Задачи (план, статус) | `summary/tasks/` |
| OpenSpec change | `openspec/changes/` → `archive/` |
| OpenSpec specs | `openspec/specs/` |
| Код/скрипты | проект |
| Git | commit + push |

## Признак завершения

1. ✅ Все 4 шага пройдены
2. ✅ Git clean (только файлы задачи закоммичены)
3. ✅ `git status` — нет незакоммиченных изменений

## Действия

1. **Спросить тему/название задачи** если не ясно из контекста
2. **Спросить какие файлы зафиксировать** если не очевидно
3. **Создать аудит и таски** по шаблону выше
4. **Закоммитить и запушить**
5. **Показать итоговую сводку**

## Пример диалога

```
Пользователь: фиксация
Агент: По какому вопросу фиксация?
Пользователь: добавили автотесты для рендеринга
Агент: Фиксирую задачу "Автотесты для рендеринга"
       - Создаю summary/audit/002_auto-tests.md
       - Создаю summary/tasks/002_auto-tests.md
       - Коммичу изменения
       - Push на GitHub
```

## Важно

- Если есть active OpenSpec change — архивировать его
- Всегда спрашивать тему если не ясно
- После фиксации показать что было сделано
- Пушить на GitHub если remote настроен
